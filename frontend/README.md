# ShipFlow Frontend

React frontend for the ShipFlow SaaS application. It consumes the versioned
ShipFlow REST API from the separate `shipflow-backend` repository.

## Requirements

- Node.js 24
- npm 11
- ShipFlow backend and PostgreSQL for live API development

## Local Setup

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

The frontend runs at `http://localhost:5173`. The default API URL is
`http://localhost:3000/api/v1`.

## Environment

| Variable                    | Purpose                           | Local default                         |
| --------------------------- | --------------------------------- | ------------------------------------- |
| `VITE_API_BASE_URL`         | Versioned REST API base URL       | `http://localhost:3000/api/v1`        |
| `VITE_APP_URL`              | Public URL of the frontend        | `http://localhost:5173`               |
| `VITE_GOOGLE_OAUTH_ENABLED` | Display Google authentication     | `false`                               |
| `VITE_GITHUB_OAUTH_ENABLED` | Display GitHub authentication     | `false`                               |
| `OPENAPI_URL`               | Build-time OpenAPI generation URL | `http://localhost:3000/api/docs-json` |

Only variables prefixed with `VITE_` are exposed to browser code. Never place
credentials or private keys in frontend environment files.

## Commands

```powershell
npm run dev
npm run format:check
npm run lint
npm run typecheck
npm test
npm run test:e2e
npm run build
npm run api:generate
```

Run `npm run api:generate` while the backend Swagger endpoint is available.
Generated contract types are committed so clean frontend checkouts can build
without a running backend.

## Architecture

- TanStack Query owns server state and request caching.
- Zustand holds only the in-memory access token and active organization ID.
- Native `fetch` is wrapped by `src/api/api-client.ts` for JSON, bearer tokens,
  credentialed cookie requests, standard API errors, request IDs, and one
  coordinated token refresh.
- React Hook Form and Zod are the approved form and validation tools.
- OpenAPI types are generated by `@hey-api/openapi-ts` from the backend.
- Vitest, React Testing Library, and MSW cover unit/integration behavior;
  Playwright covers browser workflows.
- Public-only and protected route groups wait for startup session restoration
  before rendering. Authentication forms live under `src/features/auth`.

Access tokens must not be written to local storage, session storage, cookies,
URLs, or logs. Refresh tokens remain in backend-managed HttpOnly cookies.

Password and OAuth sign-ins with two-factor authentication enabled are routed
through the same five-minute verification screen. Authenticator setup and
recovery-code management live in Profile > Security; QR codes are generated
locally in the browser and recovery codes are displayed only from the response
that creates them.

See [ADR 0001](docs/adr/0001-frontend-foundation.md) for the foundation and
[ADR 0002](docs/adr/0002-frontend-authentication.md) for authentication, and
[ADR 0004](docs/adr/0004-two-factor-experience.md) for the two-factor client
flow. The authoritative product plan is
`shipflow-backend/docs/roadmaps/project-roadmap.md`.
